# HTTP API

Два эндпоинта: кодирование текста и healthcheck. Тело запроса `POST /embed`
описано pydantic-моделью, типы ответов — dataclass'ами в `schemas.py` (см.
[dataclasses.md](dataclasses.md)); всё автоматически попадает в OpenAPI-схему.

## Интерактивная документация

Поднимается вместе с сервисом (FastAPI):

- **Swagger UI** — `http://<host>:<port>/docs`
- **ReDoc** — `http://<host>:<port>/redoc`
- **OpenAPI-схема (JSON)** — `http://<host>:<port>/openapi.json`

По умолчанию порт `8001` (переопределяется `PORT` в `.env`).

## `POST /embed`

Закодировать тексты в векторы.

### Запрос

- **Content-Type:** `application/json`
- **Поле `texts`** — непустой список строк (обязательное).

```bash
curl -s -X POST http://localhost:8001/embed \
  -H 'Content-Type: application/json' \
  -d '{"texts":["первый текст","второй текст"]}'
```

### Ответ `200` — `EmbedResponse`

```json
{
  "model": "intfloat/multilingual-e5-base",
  "dim": 768,
  "count": 2,
  "embeddings": [[0.01, -0.02, "..."], [0.03, 0.04, "..."]]
}
```

| Поле         | Тип               | Значение                                    |
|--------------|-------------------|---------------------------------------------|
| `model`      | string            | Имя модели (`MODEL_NAME`).                   |
| `dim`        | int               | Размерность одного вектора.                  |
| `count`      | int               | Число векторов (== числу входных текстов).   |
| `embeddings` | list[list[float]] | Векторы, по одному на каждый входной текст.  |

### Коды ошибок

| Код   | Когда | Тело |
|-------|-------|------|
| `422` | Пустой список `texts` (валидация pydantic) или их больше `MAX_TEXTS` | `{"detail": ...}` |
| `500` | Инференс упал | `{"detail": "<текст ошибки>"}` |
| `504` | Результат не пришёл за `REQUEST_TIMEOUT` (очередь + инференс) | `{"detail": "Время ожидания кодирования истекло"}` |

### Что важно знать

- **Обработка по очереди.** Запрос встаёт в очередь и ждёт своей очереди у
  единственного воркера. Под нагрузкой время ответа = ожидание в очереди +
  инференс. Отказа из-за переполнения нет — очередь не ограничена.
- **Cold start.** Первый запрос после старта или после простоя дольше `IDLE_TTL`
  дополнительно ждёт подъёма модели в RAM (несколько секунд).
- **Префикс модели.** Асимметричные модели (e5) ждут `EMBED_PREFIX` (`query: ` и
  т.п.) — задаётся в `.env`, применяется автоматически ко всем текстам. Детали в
  [architecture.md#кодирование-текста](architecture.md#кодирование-текста).
- **Порядок сохраняется.** `embeddings[i]` соответствует `texts[i]`.

## `GET /health`

Состояние сервиса и воркера. Модель **не поднимает** — безопасно дёргать как
healthcheck и мониторинг очереди.

```bash
curl http://localhost:8001/health
```

### Ответ `200` — `HealthResponse`

```json
{ "status": "ok", "model": "intfloat/multilingual-e5-base", "loaded": false, "queue": 0 }
```

| Поле     | Тип    | Значение                                                    |
|----------|--------|-------------------------------------------------------------|
| `status` | string | Всегда `"ok"`, если процесс отвечает.                       |
| `model`  | string | Имя модели (`MODEL_NAME`).                                  |
| `loaded` | bool   | Загружена ли модель в RAM прямо сейчас.                     |
| `queue`  | int    | Сколько запросов сейчас ждёт в очереди воркера.             |

`queue` и есть «посмотреть очередь»: это её текущая длина. Списка задач с их
статусами по замыслу нет — API синхронный: клиент держит запрос открытым до
ответа, так что job ID и промежуточные статусы не нужны.

В `docker-compose.yml` этот эндпоинт используется как healthcheck контейнера
(периодический `GET /health`); он не поднимает модель, поэтому не мешает выгрузке
по простою.

## Границы сервиса

Сервис занят одним делом — кодированием текста в векторы — и рассчитан на работу
внутри доверенной сети, за шлюзом. Всё, что относится к периметру, намеренно
живёт на внешнем слое (reverse proxy / API-шлюз), а не здесь:

- аутентификация и авторизация;
- HTTPS (TLS) — сам процесс слушает обычный HTTP;
- CORS;
- rate limiting.
