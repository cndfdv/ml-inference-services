# Text Embedder — standalone-сервис (sentence-transformers, CPU, Docker)

HTTP-сервис кодирования текста в векторы (эмбеддинги). Инференс на
sentence-transformers поверх torch, работает **только на CPU**, запросы
обрабатываются по очереди одним воркером, а модель **выгружается из RAM при
простое** и поднимается обратно по запросу. Модель — любая с HuggingFace, задаётся
одной переменной. Вся конфигурация — в `.env`, всё запускается через Docker.

Сделан по образцу соседнего сервиса `../asr-gigaam` (та же архитектура: очередь +
поток-воркер + ленивая загрузка/выгрузка модели).

## Состав

| Файл                 | Назначение                                                  |
|----------------------|-------------------------------------------------------------|
| `app.py`             | HTTP-слой (FastAPI: роуты `/embed`, `/health`)             |
| `embedder.py`        | поток-воркер: очередь, загрузка/выгрузка модели, инференс  |
| `config.py`          | конфигурация из env (`Settings`-dataclass) + логгер        |
| `schemas.py`         | контракты API (запрос/ответы для OpenAPI)                 |
| `download_model.py`  | разовое скачивание модели с HuggingFace в кеш             |
| `Dockerfile`         | рантайм-образ (torch CPU-only + sentence-transformers)    |
| `docker-compose.yml` | сервис + профиль `prepare` (скачивание модели)            |
| `.env.example`       | шаблон настроек                                            |
| `requirements.txt`   | зависимости рантайма                                       |
| `docs/`              | техническая документация (архитектура, API, структуры)     |

Подробная техническая документация — в [`docs/`](docs/README.md): как всё
устроено внутри ([architecture](docs/architecture.md)), полное описание

## Быстрый старт

```bash
# 1. настройки
cp .env.example .env        # при желании поправь MODEL_NAME, PORT, OMP_NUM_THREADS

# 2. разовое скачивание модели с HuggingFace в кеш (./models)
docker compose --profile prepare run --rm prepare

# 3. поднять сервис
docker compose up -d --build
```

Шаг 2 объявлен под профилем `prepare`, поэтому обычным `docker compose up` он не
поднимается — запускается только явной командой (разово, `run --rm`). Он лишь
прогревает кеш, чтобы сервис не качал модель во время первого запроса; можно и
пропустить — тогда модель скачается лениво при первом `/embed`. Шаг 3 поднимает
сам сервис `embedder`.

Проверка:

```bash
curl -s -X POST http://{host}:{port}/embed \
  -H 'Content-Type: application/json' \
  -d '{"texts":["привет мир","тест"]}'
# {"model":"deepvk/USER-bge-m3","dim":1024,"count":2,"embeddings":[[...],[...]]}

curl http://{host}:{port}/health
# {"status":"ok","model":"deepvk/USER-bge-m3","loaded":false,"queue":0}
```

## API

Интерактивная документация поднимается вместе с сервисом:

- **Swagger UI** — `http://localhost:8001/docs`
- **ReDoc** — `http://localhost:8001/redoc`
- **OpenAPI-схема** — `http://localhost:8001/openapi.json`

### `POST /embed`

Закодировать тексты в векторы.

- **Тело:** `application/json`, поле `texts` — непустой список строк.

  ```json
  { "texts": ["первый текст", "второй текст"] }
  ```

- **Ответ `200`** (`EmbedResponse`):

  ```json
  {
    "model": "deepvk/USER-bge-m3",
    "dim": 1024,
    "count": 2,
    "embeddings": [[0.01, -0.02, ...], [0.03, 0.04, ...]]
  }
  ```

  | Поле         | Тип             | Значение                                      |
  |--------------|-----------------|-----------------------------------------------|
  | `model`      | string          | имя модели (`MODEL_NAME`)                     |
  | `dim`        | int             | размерность одного вектора                    |
  | `count`      | int             | число векторов (== числу входных текстов)     |
  | `embeddings` | list[list[float]] | векторы, по одному на каждый текст          |

- **Ошибки:**

  | Код   | Когда                                                        |
  |-------|--------------------------------------------------------------|
  | `422` | пустой список `texts` или их больше `MAX_TEXTS`              |
  | `500` | инференс упал                                                |
  | `504` | результат не пришёл за `REQUEST_TIMEOUT`                      |

### `GET /health`

Состояние сервиса и воркера. Модель не поднимает — годится как healthcheck.

- **Ответ `200`** (`HealthResponse`):

  ```json
  { "status": "ok", "model": "deepvk/USER-bge-m3", "loaded": false, "queue": 0 }
  ```

  | Поле     | Тип    | Значение                                              |
  |----------|--------|-------------------------------------------------------|
  | `status` | string | всегда `"ok"`, если процесс отвечает                  |
  | `model`  | string | имя модели (`MODEL_NAME`)                             |
  | `loaded` | bool   | загружена ли модель в RAM прямо сейчас                |
  | `queue`  | int    | сколько запросов ждёт в очереди воркера               |

## Настройки (.env)

| Переменная             | По умолчанию                    | Назначение                                      |
|------------------------|---------------------------------|-------------------------------------------------|
| `MODEL_NAME`           | `deepvk/USER-bge-m3`            | имя HF-модели для sentence-transformers         |
| `HF_HOME`              | `/app/models`                   | кеш HuggingFace с весами (том `./models`)       |
| `HF_TOKEN`             | *(пусто)*                       | токен HuggingFace для приватных/gated-моделей и снятия лимитов загрузки |
| `IDLE_TTL`             | `120`                           | сек простоя до выгрузки модели из RAM           |
| `REQUEST_TIMEOUT`      | `300`                           | макс. ожидание результата, сек; дольше — `504`  |
| `BATCH_SIZE`           | `32`                            | размер батча при кодировании (выше — быстрее, больше памяти) |
| `NORMALIZE_EMBEDDINGS` | `true`                          | L2-нормализация векторов (удобно для косинуса)  |
| `EMBED_PREFIX`         | *(пусто)*                       | префикс к каждому тексту (bge-m3 не нужен; для e5 — `query: `) |
| `MAX_TEXTS`            | `256`                           | предел числа текстов в запросе; больше — `422`  |
| `OMP_NUM_THREADS`      | `4`                             | потоки CPU для torch (≈ число физ. ядер)        |
| `PORT`                 | `8001`                          | порт на хосте                                   |

> Модель меняется одной переменной `MODEL_NAME` — любая эмбеддинг-модель с
> HuggingFace, совместимая с sentence-transformers. Поменял модель? Прогони шаг 2
> для новой (или просто перезапусти сервис — скачается лениво), затем
> `docker compose up -d`.

### Про `EMBED_PREFIX`

Дефолтная `deepvk/USER-bge-m3` **симметричная** — префикс ей не нужен, оставляй
`EMBED_PREFIX` пустым. То же для `sergeyzh/rubert-tiny-turbo`,
`sentence-transformers/all-MiniLM-L6-v2` и прочих симметричных моделей.

Префикс нужен **асимметричным** моделям `intfloat/multilingual-e5-*`: они ждут
`query: ` для поисковых запросов и `passage: ` для индексируемых документов.
Если переключаешься на e5, выставь в `.env`:

```
EMBED_PREFIX=query:
```

(с завершающим пробелом).

## Как это работает

- Запросы складываются в очередь (без ограничения по размеру); обрабатывает их
  один поток-воркер, который единолично владеет моделью. Параллельный инференс
  на CPU смысла не имеет, а единоличное владение избавляет от блокировок и гонок.
- Модель не грузится при старте контейнера. Первый запрос поднимает её в RAM
  (cold start — несколько секунд; если модель ещё не в кеше, добавится время на
  скачивание с HuggingFace — поэтому есть шаг `prepare`).
- Инференс — на `sentence-transformers` поверх torch (CPU): библиотека сама
  качает модель с HuggingFace по имени (`MODEL_NAME`) и кодирует тексты батчами
  по `BATCH_SIZE`.
- Тот же воркер выгружает модель из RAM, если запросов не было дольше
  `IDLE_TTL`. Следующий запрос поднимает её заново.
- Результат не пришёл за `REQUEST_TIMEOUT` → `504`.

`--workers 1` в `Dockerfile` — принципиально: иначе каждый воркер держит свою
копию модели в RAM, и экономия памяти теряется.

> **torch CPU-only.** В `Dockerfile` torch ставится с индекса
> `download.pytorch.org/whl/cpu`, чтобы не тянуть CUDA-колёса и не раздувать образ.

## Про выгрузку из RAM — что реально происходит

При простое сервис удаляет модель (`self._model = None`) и зовёт `gc.collect()`.
Веса — крупные аллокации, в большинстве случаев возвращаются ОС. Остаётся базовый
«хвост» процесса (интерпретатор + torch + библиотеки, ~несколько сотен МБ). То
есть основная память освобождается, но контейнер не падает в ноль.

Хочешь **гарантированный** возврат всей памяти при простое — инференс выносится
в процесс-воркер, который убивается по таймауту и спавнится по запросу. Это
+немного кода; скажи — допишу.

## Локальный запуск без Docker (опционально)

`app.py` сам подхватит `.env` (через `python-dotenv`):

```bash
pip install -r requirements.txt python-dotenv
# модель скачается с HuggingFace в кеш (HF_HOME, по умолчанию ~/.cache/huggingface)
uvicorn app:app --host 0.0.0.0 --port 8001 --workers 1
```
