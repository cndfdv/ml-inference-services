# HTTP API

Два эндпоинта: распознавание и healthcheck. Типы тел ответов описаны
dataclass'ами в `schemas.py` (см. [dataclasses.md](dataclasses.md)) и
автоматически попадают в OpenAPI-схему.

## Интерактивная документация

Поднимается вместе с сервисом (FastAPI):

- **Swagger UI** — `http://<host>:<port>/docs`
- **ReDoc** — `http://<host>:<port>/redoc`
- **OpenAPI-схема (JSON)** — `http://<host>:<port>/openapi.json`

По умолчанию порт `8002` (переопределяется `PORT` в `.env`).

## `POST /ocr`

Распознать текст на изображении или в PDF.

### Запрос

- **Content-Type:** `multipart/form-data`
- **Поле `file`** — изображение или PDF (обязательное).
- **Принимаемые расширения:** `png`, `jpg`, `jpeg`, `tiff`, `tif`, `bmp`,
  `webp`, `pdf`.

```bash
curl -F "file=@scan.pdf" http://localhost:8002/ocr
```

### Ответ `200` — `OcrResponse`

```json
{
  "model": "PaddlePaddle/PaddleOCR-VL",
  "pages": 2,
  "text": "страница 1\n\n---\n\nстраница 2",
  "page_texts": ["страница 1", "страница 2"]
}
```

| Поле         | Тип          | Значение                                                |
|--------------|--------------|---------------------------------------------------------|
| `model`      | string       | Имя HF-модели (`MODEL_NAME`).                           |
| `pages`      | int          | Число распознанных страниц (картинка — 1, PDF — по числу страниц). |
| `text`       | string       | Весь текст, страницы склеены через `PAGE_SEPARATOR`.    |
| `page_texts` | list[string] | Текст по одной строке на страницу; порядок = порядку страниц. |

Модель гоняется через transformers как VLM (element-level): распознаёт картинку
целиком по промпту `OCR_PROMPT`, без layout-пайплайна PaddleOCR. Для сложной
вёрстки результат менее структурирован, чем в полном пайплайне `paddleocr`.

### Коды ошибок

| Код   | Когда | Тело |
|-------|-------|------|
| `415` | Неподдерживаемое расширение файла | `{"detail": "Неподдерживаемый формат '...'. Принимаем: ..."}` |
| `422` | Не передан файл `file` (валидация FastAPI) | стандартный `{"detail": [...]}` |
| `500` | Инференс упал | `{"detail": "<текст ошибки>"}` |
| `504` | Результат не пришёл за `REQUEST_TIMEOUT` (очередь + инференс) | `{"detail": "Время ожидания распознавания истекло"}` |

### Что важно знать

- **Обработка по очереди.** Запрос встаёт в очередь и ждёт своей очереди у
  единственного воркера. Под нагрузкой время ответа = ожидание в очереди +
  инференс. Отказа из-за переполнения нет — очередь не ограничена.
- **Cold start.** Первый запрос после старта или после простоя дольше `IDLE_TTL`
  дополнительно ждёт подъёма модели в RAM.
- **Скорость на CPU.** PaddleOCR-VL — VL-модель ~1B параметров; на CPU
  генерация медленная, особенно многостраничный PDF. Отсюда большой
  `REQUEST_TIMEOUT` по умолчанию.
- **PDF.** Рендерится в картинки постранично через pypdfium2 (DPI = `PDF_DPI`,
  системный poppler не нужен) и распознаётся по странице — от клиента ничего
  дополнительно не требуется, страницы возвращаются в `page_texts`.

## `GET /health`

Состояние сервиса и воркера. Модель **не поднимает** — безопасно дёргать как
healthcheck и мониторинг очереди.

```bash
curl http://localhost:8002/health
```

### Ответ `200` — `HealthResponse`

```json
{ "status": "ok", "model": "PaddlePaddle/PaddleOCR-VL", "loaded": false, "queue": 0 }
```

| Поле     | Тип    | Значение                                                    |
|----------|--------|-------------------------------------------------------------|
| `status` | string | Всегда `"ok"`, если процесс отвечает.                       |
| `model`  | string | Имя HF-модели (`MODEL_NAME`).                               |
| `loaded` | bool   | Загружена ли модель в RAM прямо сейчас.                     |
| `queue`  | int    | Сколько запросов сейчас ждёт в очереди воркера.             |

`queue` и есть «посмотреть очередь»: это её текущая длина. Отдельного эндпоинта
со списком задач / их статусами нет — задел на будущее (job ID + статусы).

В `docker-compose.yml` этот эндпоинт используется как healthcheck контейнера
(периодический `GET /health`); он не поднимает модель, поэтому не мешает выгрузке
по простою.

## Чего в API пока нет

Сервис рассчитан на доверенную сеть. Для публичного доступа не хватает:

- аутентификации / авторизации;
- HTTPS (TLS) — сейчас только plain HTTP;
- CORS-политики;
- rate limiting;
- эндпоинта со списком/статусами задач в очереди (есть только длина в `/health`).
